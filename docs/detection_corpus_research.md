# Fresh syringe detection benchmark

Public source and repository metadata reviewed on 2026-11-21. The proposed benchmark measures whole-syringe localization and false alarms on lookalikes. Archive contents, final sample counts, acquisition independence, and local model performance remain unverified.

## Recommended corpus

Build a locked Commons cohort of real syringe scenes and hard negatives. Use the CC BY 4.0 dental dataset as a separate controlled challenge for metal aspirating syringes and similarly shaped tools. MedBin is the strongest additional lead for matched positive and negative scenes in medical clutter, pending verification of the exact public export and its lineage. Keep the existing Fil Rouge, Zenodo, Commons and Open Images cohorts as regression evidence. In particular, the project has already used 74 unique frames from one Fil Rouge acquisition, and its Zenodo study found clip IDs shared across the publisher's splits. Further frames from these acquisitions cannot establish external generalization. [Project protocol](protocol.md) · [Zenodo dataset](https://doi.org/10.5281/zenodo.16924786) · [Phlebotomy data article](https://arxiv.org/html/2602.04624v1) · [Project clip audit](rfdetr_transfer.md) · [Earlier lookalike evaluation](rfdetr_verification.md)

## Staging and evaluation

1. **Budget the pilot.** Aim for 40 positive and 40 syringe-free photographic scenes across at least 60 capture groups, with matched settings on both sides where possible. At 0.3–3.2 MB per Commons original, budget roughly 25–260 MB, plus derivatives. Allow 4–8 person-hours for metadata selection, box annotation and an independent review of this small pilot. For planning only, at 0.1–0.5 MB per exported image, 2,178 dental files cost about 0.22–1.1 GB and 1,796 MedBin files cost about 0.18–0.90 GB before extra copies. Reserve about 5 GB for archives, extraction and working subsets. Actual archive sizes are unverified. Mendeley offers a download control for dental v1. Use a free COCO ZIP export for MedBin only if the published version can be obtained without payment or uploading project data. For SID-RAS, obtain a file list and archive byte counts after resolving the terms. Budget for manual provenance review before committing to a bulk download. [Dental dataset card](https://data.mendeley.com/datasets/mh6zpc7y9g/1) · [SID-RAS card](https://data.mendeley.com/datasets/cyghvmjrt3/1) · [MedBin v1 export card](https://universe.roboflow.com/medical-waste-e3vov/medbin_dataset-2/dataset/1) · [Roboflow export documentation](https://docs.roboflow.com/datasets/versions/dataset-versions/exporting-data)
2. **Group before splitting or augmentation.** Extend the existing manifest practice with source version and original URL, file ID, declared license, orientation, raw SHA-256, decoded-image hash, perceptual hash, parent image or clip, and a pseudonymous capture group. Compare normalized source IDs, license/credit aliases, timestamps, hashes and visual neighbors against every staged split, including earlier reserves and crops. Keep mirrors, resize/crop variants, overlapping compositions and uncertain families together. Search for duplicates using the project's 64-bit difference-hash cutoff (Hamming distance ≤4) plus visual review for rotated, cropped or reframed versions. Keep public pretraining overlap as an explicit unknown. [Project protocol](protocol.md) · [Project reserve audit](rfdetr_transfer.md) · [Prior per-file manifests](rfdetr_verification.md)
3. **Use the project box convention.** Label every visible syringe instance in the full scene, including integral components and attached tips per the existing annotation rule. Keep capped, hand-held, partially occluded, truncated, overlapping and small instances, with explicit slice tags. Record dental aspirating syringes as a separately reported positive subtype. Review syringes in wrappers, needle-only scenes, pen injectors and uncertain objects under a written inclusion rule before scoring. Tag clear pipettes, ampoules, droppers, markers, pens and tubular tools as distractors. A negative scene requires human verification that no in-scope syringe is visible. A missing label or bounding box for a plastic part or drug label is insufficient. [Project annotation protocol](protocol.md) · [Observed lookalike errors](precision_study.md)
4. **Freeze and score once.** Use development-only groups for fine-tuning, hard-negative mining, threshold calibration and tile selection. Lock the test manifest, references, preprocessing, weights and thresholds before prediction. Report box AP50–95 and AP50 when the full score range is available, then precision, recall, exact count, false positives per negative scene, fraction of hard-negative scenes with any false alarm, and gains/losses of specific baseline matches at IoU ≥0.50. Give image, instance and independent-group counts for each source and slice. Use group-level intervals where counts support them. The positive/negative mix is deliberately enriched for errors, so report its precision at the measured mix and avoid extrapolating field prevalence. [Project protocol](protocol.md) · [Existing threshold and release checks](rfdetr_verification.md)

## Local architecture shortlist for 2026

Use the currently deployed detector as the release comparator and RF-DETR Nano detection as the supervised control. The local Core Ultra 7 258V has Arc 140V shared graphics, about 30 GiB usable memory, and a demonstrated CPU RF-DETR fine-tuning path at reduced resolution. Whole-scene box detection can be compared independently of masks, markings and fill measurements. [Hardware and reference models](research.md) · [Existing CPU training run](rfdetr_transfer.md)

| Candidate | Exact permissive artifact and practical path |
| --- | --- |
| **D-FINE Nano, then Small** | First architecture challenger. The upstream Apache-2.0 source and maintainer-confirmed Apache-2.0 COCO-only `dfine_n_coco.pth` and `dfine_s_coco.pth` are about 15.5 and 41.8 MB, respectively, from the release manifest. The publisher lists 4M and 10M parameters and 42.8 and 48.5 COCO AP. It documents custom detection data, ONNX export and ONNX Runtime inference. Start with Nano and validate the exported graph on CPU and OpenVINO GPU locally. Use the COCO-only files. The `_obj365` and `_obj2coco` lineages carry separate dataset concerns which the publisher explicitly flags. [Upstream model zoo and deployment](https://github.com/Peterande/D-FINE) · [Maintainer checkpoint license clarification](https://github.com/Peterande/D-FINE/issues/357) · [Release asset metadata](https://api.github.com/repos/Peterande/storage/releases/tags/dfinev1.0) |
| **YOLOX-Tiny via Intel Geti / OpenVINO** | A lightweight convolutional, anchor-free alternative to the DETR models. Megvii's code is Apache-2.0 and Intel's exact Geti FP16 and INT8 IR cards mark the weights Apache-2.0. The FP16 package is approximately 10.5 MB. Use the IR for an inference path smoke test. For training, Intel documents Geti's local fine-tuning and export path on supported CPU and Intel GPU configurations. Pin the actual training initializer and record its license. The Texas Instruments COCO card lists the original PyTorch Tiny release under its Apache-2.0 model listing, with the exact upstream asset referenced in its file tree. [Upstream license](https://github.com/Megvii-BaseDetection/YOLOX/blob/main/LICENSE) · [Intel FP16 card and license](https://huggingface.co/OpenVINO/yolox_tiny-fp16-ov) · [FP16 files](https://huggingface.co/OpenVINO/yolox_tiny-fp16-ov/tree/main) · [Intel INT8 card and license](https://huggingface.co/OpenVINO/yolox_tiny-int8-ov) · [Geti local training and export](https://github.com/open-edge-platform/geti) · [Texas Instruments exact initializer reference](https://huggingface.co/TexasInstruments/YOLOX-Detection/blob/main/yolox_tiny.pth.link) |
| **RF-DETR Nano detection / Seg Nano control** | Apache-2.0 applies to the standard package, Nano/Small/Medium/Large detection weights and all Seg sizes per the publisher. Use Nano detection for matching box supervision and the existing Seg Nano branch to test whether transfer or masks add value. ONNX and OpenVINO export are documented. Atto, Femto, Pico, XL and 2XL **detection** weights use PML 1.0 and have different self-hosting terms. [Checkpoint license matrix](https://rfdetr.roboflow.com/latest/learn/pretrained/) · [OpenVINO export](https://rfdetr.roboflow.com/latest/exports/openvino/) |
| **RT-DETRv4 Small**, conditional | An ECCV 2026 challenger with 49.8 reported COCO AP, an Apache-2.0 implementation, published checkpoints and an ONNX path. The default training recipe distills a DINOv3 teacher under Meta's custom DINOv3 License. The teacher is absent at inference. The inspected publisher material did not establish a separate permissive grant for the exact released student checkpoint, so defer it for a permissive release pending confirmation of the artifact and lineage terms. Default teacher-based training also adds memory and setup cost. [Original paper](https://arxiv.org/abs/2510.25257) · [Official repo and recipe](https://github.com/RT-DETRs/RT-DETRv4) · [DINOv3 license](https://github.com/facebookresearch/dinov3/blob/main/LICENSE.md) |

DEIMv2 currently uses its custom noncommercial license for the project and publisher weights unless a separate license applies. Ultralytics YOLO26 uses AGPL-3.0 under the vendor's default terms. They fall outside this permissive shortlist. [DEIMv2 license](https://github.com/Intellindust-AI-Lab/DEIMv2/blob/main/LICENSE.md) · [Ultralytics licensing](https://www.ultralytics.com/license)

For a first local comparison, use identical group assignments, box labels and supervised update budgets. Compare native input sizes and record a matched-resolution run if differences affect small-object recall. Measure end-to-end batch-one latency and peak memory with warmup on CPU and, where supported, Arc via OpenVINO. Establish FP32 box and score parity before trying FP16 or INT8, and use development-only scenes for INT8 calibration. Record preprocessing, box mapping and postprocessing, especially for long, thin objects and tiled inference. Published COCO and NVIDIA timings provide model-size context. Local latency, export parity and syringe accuracy require measurement.
