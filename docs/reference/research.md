# Local vision for 75 syringe images

Sources checked 2026-11-20. Target hardware is Intel Core Ultra 7 258V with Arc 140V integrated graphics and 32 GB of memory. This is a literature and documentation review. All timings below come from their named publishers. Local execution, syringe accuracy, and annotation effort remain unmeasured. No user images were accessed or uploaded for this review, and no independent dataset was assembled. [Intel processor specifications](https://www.intel.com/content/www/us/en/products/sku/240957/intel-core-ultra-7-processor-258v-12m-cache-up-to-4-80-ghz/specifications.html)

## Recommended starting point

Use **CVAT Community** locally and label the 75 images directly. Start with one syringe class and boxes. Add a rotated box, two barrel-axis landmarks, or an instance mask only if crop alignment, overlapping objects, or silhouette quality requires it. A small comparison between manual annotation and reviewed text-grounded proposals can establish whether proposals save time. For inference, start with an OpenCV baseline where capture geometry is consistent, then use **RF-DETR Nano** as the first supervised candidate with explicitly Apache-2.0 weights. **YOLO26n** has the strongest published performance evidence for this chip and is a useful comparison when the intended use can meet Ultralytics' license terms. Run OCR on original-resolution barrel crops. Keep SAM 3.1 for a future contiguous-video use case with a verified supported runtime. [CVAT Community](https://docs.cvat.ai/docs/products/community/) · [RF-DETR pretrained models](https://rfdetr.roboflow.com/latest/learn/pretrained/) · [Ultralytics Intel benchmarks](https://docs.ultralytics.com/integrations/openvino/#intel-core-ultra-cpu-gpu-and-npu) · [Ultralytics licensing](https://www.ultralytics.com/license) · [Meta SAM 3.1 release](https://github.com/facebookresearch/sam3/blob/main/RELEASE_SAM3p1.md)

## Preserve image coordinates and account for identity leakage

- Decode the primary HEIC image locally with Pillow and pillow-heif into an upright, full-resolution RGB working image. Select the primary image explicitly if a container has auxiliary images. Check orientation against the rendered pixels before creating annotations, since HEIF transforms and EXIF/XMP orientation can interact. Keep originals and stable IDs, record the working dimensions and any spatial transform, and use lossless working copies for OCR. For redistribution, pillow-heif's BSD-3-Clause source license and the bundled native library and codec notices are separate. [pillow-heif orientation notes](https://pillow-heif.readthedocs.io/en/latest/workaround-orientation.html) · [Bundled licenses](https://github.com/bigcat88/pillow_heif/blob/master/LICENSES_bundled.txt)
- Treat 75 frames as at most 75 observations and potentially one acquisition group. Repeated physical syringes, burst neighbors, and shared capture conditions can leak even with different filenames and poses. Before tuning, record known session, physical specimen and capture sequence IDs locally. Use timestamps, visual similarity and duplicate hashes as grouping aids, and keep uncertain or linked groups together. If the same physical syringe spans sessions, keep those sessions together when estimating generalization to new syringes. Keep every crop, resized copy and augmentation with its source. [scikit-learn grouped cross-validation](https://scikit-learn.org/stable/modules/cross_validation.html#cross-validation-iterators-for-grouped-data)
- If the existing material already has enough separable groups, freeze group assignments before preprocessing for training, augmentation, or threshold tuning. Report image and group counts and the error counts by group. If everything comes from one session, any frame- or within-session specimen-level comparison is a development diagnostic. Generalization to a new session stays unmeasured. A single group cannot support group-based cross-validation. The scope of this review is the existing 75 images. [GroupKFold requirements](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.GroupKFold.html)

For a later local comparison, use the same images and batch size. Compare each checkpoint at its documented input size first, then measure any larger-input variant separately. Choose model-specific thresholds on development data and freeze them before scoring an eligible held-out group. Keep preprocessing and thresholds fixed when comparing devices or precisions for a single checkpoint. First check that `Core().available_devices` exposes the Arc and verify the selected adapter name. Use explicit OpenVINO `CPU` and `GPU` runs, since `AUTO` can start on CPU. Record model revision, runtime and driver, input dimensions, execution precision, cold load/compile time and warmed median/p95 latency. Separately time HEIC decode, resize, inference, postprocessing, and OCR. Keep the training checkpoint and ONNX export for portability, plus OpenVINO IR for Intel. Confirm that output coordinates, confidence and mask quality match the reference before changing precision. Roboflow documents RF-DETR score collapse in one FP16 test on Apple M4 Max and recommends explicit FP32 execution for parity. PyTorch XPU supports Lunar Lake, while model-specific training and operators still need verification. ## OCR and tracking

- **OCR.** Crop from the original-resolution RGB image and rotate the barrel to align text. Compare Tesseract with `tessdata_fast` and a line or word segmentation mode against PP-OCRv5 mobile recognition. Add the mobile text detector where text location varies. PaddlePaddle also publishes PP-OCRv6 tiny detector and recognizer in ONNX as a portability option. Tesseract engine and `tessdata_fast` are separately Apache-2.0. PaddleOCR engine and these named weights are each published under Apache-2.0. Intel reports up to **4×** faster PP-OCRv5 inference with OpenVINO on the 258V iGPU versus CPU in a partner brief. The text and capture conditions here remain unmeasured. For printed labels, log exact field-match and abstention rates on manually transcribed visible text, with particular attention to decimals and units. Graduation marks and plunger position are separate geometry tasks. Use an explicit unreadable state for glare, clipping and low-confidence characters. [Tesseract quality guide](https://tesseract-ocr.github.io/tessdoc/ImproveQuality.html) · [Engine](https://github.com/tesseract-ocr/tesseract/blob/main/LICENSE) · [Trained data](https://github.com/tesseract-ocr/tessdata_fast/blob/main/LICENSE) · [PaddleOCR code](https://github.com/PaddlePaddle/PaddleOCR/blob/main/LICENSE) · [PP-OCRv5 mobile detection](https://huggingface.co/PaddlePaddle/PP-OCRv5_mobile_det) · [PP-OCRv5 mobile recognition](https://huggingface.co/PaddlePaddle/PP-OCRv5_mobile_rec) · [PP-OCRv6 ONNX detector](https://huggingface.co/PaddlePaddle/PP-OCRv6_tiny_det_onnx) · [PP-OCRv6 ONNX recognizer](https://huggingface.co/PaddlePaddle/PP-OCRv6_tiny_rec_onnx) · [Intel partner brief](https://cdrdv2-public.intel.com/864387/Baidu%20Partner%20Brief_v5.pdf)
- **Tracking.** Treat stills independently unless there is a real, temporally ordered sequence with usable continuity. For one object and nearby frames, sparse Lucas–Kanade optical flow with periodic re-detection is a checkpoint-free CPU baseline. For several objects, feed boxes and scores from the selected detector into ByteTrack's MIT-licensed association code. Association needs no extra trained weights. The optional bundled detector examples have their own checkpoint provenance. Reset at gaps or cuts and review ID switches and fragmentation when objects overlap. Track IDs are sequence-local and provide only tentative evidence for grouping physical specimens. Use CVAT interpolation only for contiguous sequences and confirm keyframes at occlusion and reappearance. [OpenCV optical flow](https://docs.opencv.org/4.x/d4/dee/tutorial_optical_flow.html) · [ByteTrack integration](https://github.com/FoundationVision/ByteTrack) · [ByteTrack code license](https://github.com/FoundationVision/ByteTrack/blob/main/LICENSE) · [CVAT track mode](https://docs.cvat.ai/docs/annotation/manual-annotation/modes/track-mode-basics/)

For a portable local workflow, keep original-image IDs linked to the CVAT backup and COCO export. Maintain group and split assignments separately from tool-generated rebalancing. For each model artifact, retain the source revision and license, class mapping, input color and resize conventions, output decoding and thresholds. Check one export/import round trip before committing the project's labels to a format. Report localization misses and false positives by group at a stated IoU and confidence policy. If masks are required, also check whether thin structures and overlaps survive. Track OCR exact matches and annotation correction time alongside detector quality. If the collection is one session, use those figures to decide whether a pipeline is worth pursuing and leave out-of-session quality open.
