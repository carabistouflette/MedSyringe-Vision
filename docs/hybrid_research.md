# Hybrid detection for small transparent syringes

Research checked 20 November 2026. The target is local inference on the project CPU or Intel Arc 140V, with limited labels, the existing original photos, and public supplemental sources. This review used public documentation and existing repository results. It ran no new model, data collection, upload, or hardware benchmark.

## What the project has measured

The 21-image supervised audit recorded 7 TP and 17 FP for the released detector, 1 TP and 0 FP for full-frame SSDLite, and 4 TP and 6 FP for the earlier score-fusion candidate. Fusion improved point precision from 0.292 to 0.400 and lost three true detections. The follow-up scale ablation on that already inspected audit retrieved zero targets with aspect-preserving 320 px input and two with 512 px. [Supervised study](supervised_training.md)

The additive calibration artifact records a different experiment on 17 previously inspected public scenes. The released detector matched five of six syringe boxes and produced nine FP. The 72 combinations of SSDLite views, auxiliary score, and below-cutoff detector corroboration preserved the five matches and recovered zero further targets. Tile-only configurations added one to three FP. The artifact records no selected setting. The later experiment bound the public-photo manifest before evaluating the visual-prompt model. The tested slicer takes four overlapping corner crops covering 66% of each image dimension and discards boxes near internal tile edges. The add-on also requires an overlapping below-cutoff released-detector proposal. The aggregate results leave open whether the missed syringe was absent from the raw tile proposals, lost to edge or duplicate filtering, or lacked sufficient corroboration. ## Tiling and ROI routing

SAHI established overlapping slices and optional full-image inference with box merging. Recent work supports comparing that simple baseline with adaptive policies. The 2025 GOIS paper reallocates slices to likely ROIs in VisDrone and xView. A 2026 ROI-Gated SAHI preprint found that applying its gate to every COCO128 image lowered AP50 from 0.757 to 0.660 and was slower than full SAHI. Its adaptive route was only 1.02× faster on average. A November 2026 preprint found that a higher-resolution single pass beat tiled box fusion on VisDrone for the models that could be trained at that resolution. Its dense fusion worked better on very large DOTA scenes, but operates on pre-decoding detector outputs. These results motivate controls and measurements on syringe images. [SAHI paper and implementation](https://github.com/obss/sahi) · [GOIS](https://doi.org/10.1016/j.neucom.2025.130327) · [ROI-Gated SAHI](https://arxiv.org/abs/2608.23923) · [Resolution and coverage-aware fusion preprint](https://arxiv.org/abs/2611.12657v4)

1. **Find the stage losing recall.** On development groups, count reference matches in raw full-frame and tiled SSDLite proposals, after projection and edge handling, after deduplication, and after corroboration. Measure candidate recall before gating and track novel FP at each stage. Compare full-frame SSDLite, fixed tiles, and full-frame plus tiles using the same checkpoint. Include a budget-matched higher-resolution full-frame control, documenting any model training or input changes.
2. **Size crops for syringe geometry.** Use the development distribution of short-side pixels, visible long-side pixels, and orientations to choose a small set of crop sizes and overlaps. Preserve aspect ratio, retain padding for the plunger, tip, and nearby context, and invert resizing and padding when projecting boxes. Tiling helps when scale was lost during whole-frame resize. It cannot recover detail missing in the source pixels. Check coverage of long diagonals and distinguish seams from actual frame edges. Where an internal seam clips a candidate, try a padded recrop or retain the interior detection from the adjacent tile. Compare IoU with intersection divided by smaller box area for partial duplicates. Inspect adjacent parallel syringes because containment rules can suppress distinct instances.
3. **Budget tile work and keep a fallback.** Run the released full-frame path as usual. Compare the bounded fixed grid with padded ROIs around tentative proposals and a bounded grid fallback for empty, uncertain, or poorly covered scenes. A gate that relies solely on the released detector's proposals can exclude the very targets it is meant to recover. Measure routing coverage, proposal recall, tile count, and latency on the same scenes.
4. **Keep corroboration additive.** Preserve the released accepted boxes, scores and ordering. Apply duplicate suppression and agreement thresholds to new proposals. The current below-cutoff agreement is a useful control. If it is the limiting stage, compare it with an independent local text or visual detector on padded crops. Cross-tile support from the same checkpoint is an inexpensive stability signal with correlated errors. Keep uncorroborated proposals available for offline review during development and inspect whether each added box corresponds to a new object. Count retained baseline instance matches after one-to-one assignment, since preserving prediction records alone does not guarantee identical matching.

## Local text and visual prompting

Freeze a few text prompts and development-only visual exemplars spanning barrel styles, scales, and backgrounds. Compare the same crops and candidate lists across corroborators, with thresholds calibrated per model. Use hard negatives such as ampoules, droppers, pipettes and pens. The repo's earlier semantic prompt probe found overlap between positive and lookalike scores, so synonym agreement or score margins need independent validation. For a new model smoke test, run both full-frame and padded ROI inference on development data. Full-frame only tests can hide a useful crop corroborator, and ROI only tests cannot measure independent proposal recall. [Repo semantic probe](precision_study.md)

## Public data and synthetic training

- **Public photographs first.** Seek new, independently sourced positive scenes with distant syringes, mixed orientations, occlusion, and glass or clear plastic distractors under similar lighting. Wikimedia Commons has a syringe category and per-file licensing. Open Images offers category boxes and verified image labels, with CC BY 4.0 annotations and images listed as CC BY 2.0 subject to per-image verification. The project already used its public test subset and found no syringe boxes or verified syringe rows in its V7 validation files. Exclude known used images and their derivatives. Annotate the entire image, including every syringe and confirmed empty scenes. Product listings and public search results can lead to sources, but use only assets with documented permission. [Wikimedia syringe category](https://commons.wikimedia.org/wiki/Category:Syringes) · [Commons reuse](https://commons.wikimedia.org/wiki/Commons:Reusing_content_outside_Wikimedia) · [Open Images terms and downloads](https://storage.googleapis.com/openimages/web/factsfigures_v7.html#licenses) · [Repo data protocol](protocol.md)
- **Treat community exports as leads.** One Roboflow Universe syringe version declares CC BY 4.0 and lists 2,844 images. The version count and provided partitions alone do not establish independent originals, source rights, or box conventions. Verify original provenance, labels, download requirements, augmentation and frame duplication before use. Use verified originals for development unless an independently sourced subset can be established before model selection. Record the asset URL, original creator, license and version, attribution text, derivative parent, and group. [Dataset publisher's version page](https://universe.roboflow.com/syringe-project/syringe-det/dataset/2)
- **Use transparent-object datasets for optics and distractors.** ICCV 2025 LayeredDepth publishes a CC0 benchmark with downloadable validation images and depth labels. It supplies examples of transparent appearance and would require scene review and new boxes for syringe detection. TransCG provides real RGB-D scenes with transparent objects under CC BY-NC 4.0. Restrict its use to permitted noncommercial work or omit it if the resulting artifacts need broader rights. ClearGrasp publishes real and synthetic RGB-D data and geometry. The code is Apache-2.0. Verify separate asset terms before including its downloads. [LayeredDepth release](https://github.com/princeton-vl/LayeredDepth#layereddepth-benchmark) · [TransCG data and license](https://graspnet.net/transcg) · [ClearGrasp data](https://sites.google.com/view/cleargrasp/data) · [ClearGrasp code](https://github.com/Shreeyak/cleargrasp)
- **Render a small development-only ablation.** BlenderProc supports procedural photorealistic scenes and label outputs. Use procedural or explicitly licensed meshes, textures and backgrounds. Vary barrel opacity and roughness, refraction, plunger geometry, scale, clutter, lighting and camera pose, including matching scenes with lookalikes alone. Transparent materials need physically plausible transmission, glare and occlusion. Naive cut-and-paste can carry old background pixels through the barrel and create shortcuts. Derive visible-instance boxes with a separate geometry pass and inspect agreement with the labeling convention for tips and clipped objects. Group renders by mesh, scene template and background family. Compare real-only development training with real plus synthetic at equal update budgets, and judge the outcome on real photographs. [BlenderProc code and GPLv3 license](https://github.com/DLR-RM/BlenderProc) · [LayeredDepth paper on real and synthetic transparent scenes](https://arxiv.org/abs/2503.11633)

## Leak-resistant decision protocol

1. **Assign groups before modeling.** Group burst, video, shoot, creator, product listing, mirror, and derivative families. Treat the existing single-provenance Fil rouge collection as development and regression evidence. Older external sets consulted during selection are regressions. Keep a newly sourced public holdout by group. Check URLs, exact hashes, perceptual hashes, and likely crop or mirror matches via visual inspection or local embedding retrieval. Keep tiles, augments, pseudo-labels and prompt exemplars with their parents. Public assets may overlap model pretraining, so describe this holdout as independent of project tuning with upstream overlap unknown. [Repo protocol](protocol.md) · [Visual dataset leakage study, ICCV 2025 workshop](https://openaccess.thecvf.com/content/ICCV2025W/Findings/papers/Ramos_Data_Leakage_in_Visual_Datasets_ICCVW_2025_paper.pdf)
2. **Freeze the rule and the annotations.** Define barrel, plunger, tip, needle, cap, partial objects, depictions and ambiguous negatives before reviewing model outputs. Have a second reviewer adjudicate ambiguous or thin boundaries if available. Use grouped development folds for prompt, tile and threshold choices. Freeze the candidate and holdout manifest with hashes before scoring. Treat subsequent tuning informed by that holdout as development and reserve another independent group for the next final claim.
3. **Report paired outcomes by instance and scene.** At the frozen operating point, require retention of every released-detector match at IoU ≥0.50 across the agreed regression sets and fresh holdout. For an additive release, predefine the acceptable FP budget and require extra matched instances with baseline precision maintained on the fresh holdout. With unchanged accepted detections, an additive rule targets recall and cannot remove existing FP. Report recovered and lost references, extra FP, duplicates, false positives per negative scene, precision, recall and TP/FP/FN denominators. Include AP50 and AP50–95 only when both outputs provide comparable rankings, and report slices for short-side size, elongated boxes, transparency, occlusion, group and seam proximity where counts allow. With few independent groups, report counts and uncertainty by group and treat lookalike-enriched precision as sample-specific. Use predeclared latency and memory budgets alongside the accuracy criteria. [Existing release criterion and regression evidence](supervised_training.md#recall-release-requirement)

The next development comparison with the clearest diagnostic value is raw tiled SSDLite candidate recall before any matching gate. If the raw proposals miss the target, work on scale, coverage, and labeled positives. If a viable proposal gets filtered out, test seam handling, deduplication, or a local visual/text corroborator at that stage. An eligible configuration needs a newly frozen public holdout before any deployment claim.
